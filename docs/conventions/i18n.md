# 国际化（i18n）

中英双语，`@nuxtjs/i18n`，`strategy: 'no_prefix'`（URL 不带语言前缀），zh 默认，cookie `v_locale` 记忆偏好。

## 军规

1. 组件不直接 `useI18n`，一律走 `useLocale()` 门面（`t` / `locale` / `toggleLocale`）`[Review]`
2. i18n 的 key 命名：页面 / 域命名空间.键（如 `home.title`、`login.username`）；locale 文件按页面 / 域分节组织 `[Review]`
3. 新增文案必须同步维护 `i18n/locales/zh.json` 与 `en.json` 两份，键位一致 `[Review]`
4. 业务错误码文案在域格子 `errors.ts` 映射到 `error.<code>`（如 `1001 → error.1001`），`satisfies` 穷尽检查保证不漏译 `[Review]`
5. 横幅级错误文案在全站表 `API_ERROR_BANNER_I18N`（`app/api/error.ts`），key 落 `error` 命名空间（`error.network` / `error.http` / `error.fallback`）`[Review]`
6. `COOKIE_KEYS.locale` 改动必须同步 `nuxt.config.ts` 的 `i18n.detectBrowserLanguage.cookieKey`——构建期配置引用不了登记册文件 `[Review]`
7. `<html lang>` 跟随 locale（`app/app.vue` 的 useHead 绑定），不要在别处重复设置 `[Review]`

## 门面（canonical：`app/composables/useLocale.ts`）

```ts
const { t, locale, toggleLocale } = useLocale()
```

- 语言切换按钮在 `layouts/pc.vue` 与 `m.vue`，调 `toggleLocale`；cookie 持久化由 @nuxtjs/i18n 的 `detectBrowserLanguage` 负责
- 页面 SEO 文案的取法：pages 薄壳里 `usePageMeta({ title: t('xxx.title') })`（见 [pages-and-views.md](pages-and-views.md)）

## locale 文件组织

`i18n/locales/zh.json` / `en.json` 单文件按命名空间分节：`nav` / `home` / `about` / `animation` / `login` / `me` / `error`。

- 新页面建新命名空间，键名保留完整词
- 错误文案集中在 `error` 命名空间：业务码键（`error.1001`）、横幅兜底（`error.network`、`error.http`、`error.fallback`）
- 浏览器语言检测：`redirectOn: 'root'` 只在根路径按浏览器语言重定向一次，之后 cookie 说了算

## 与错误体系的衔接

错误码 → 文案的两级收口见 [data-and-errors.md](data-and-errors.md)：字段级查域错误表（本文件的军规 4），横幅级查全站表（军规 5）；未登记的业务码兜底 `error.fallback`。
